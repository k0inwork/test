# Архитектура Новой Системы (PUM Go)

Новая реализация PUM переходит от монолитной архитектуры Django к распределенным микросервисам на Go с использованием **Service Discovery**.

## Основные Компоненты

### 1. Registry Service (Реестр Сервисов)
Центральный компонент, отвечающий за обнаружение сервисов.
- Каждый сервис при запуске регистрирует свое имя, эндпоинт и **Capability** (возможности).
- Поддерживает механизм **Heartbeat** для отслеживания работоспособности сервисов.
- GUI использует Registry для построения динамического меню.

### 2. Динамическая Модульность
Система поддерживает частичную активацию.
- **Core Services** (Identity, Product): Обязательны для работы. Если они недоступны, GUI блокирует работу приложения.
- **Optional Services** (Inventory, Network, и др.): GUI показывает соответствующие разделы только в том случае, если сервис зарегистрирован в Registry.

### 3. Конфигурация External Modules
Все внешние зависимости (LDAP, GLPI, RabbitMQ) вынесены в `system.yaml`.
- Позволяет легко переключаться между **mock** (заглушками) и **remote** (реальными подключениями) без изменения кода.

## Жизненный Цикл Сервиса
1. Сервис считывает свою конфигурацию.
2. Сервис запускает фоновую задачу регистрации в `Registry`.
3. Сервис отправляет Heartbeat каждые 30 секунд.
4. Если Registry не получает Heartbeat в течение 60 секунд, сервис считается "мертвым" и удаляется из списка доступных в GUI.

## Преимущества Реестра
- Отсутствие жестких ссылок между сервисами.
- Возможность горизонтального масштабирования.
- Автоматическое обновление интерфейса при добавлении новых модулей.
